> 基于当前代码现状整理，反映后端全部模块、数据流与质量机制的真实实现。
> 项目根：`E:\sister_train` · 提交基线：`8c2619b`

---

## 1. 项目概述

本地部署的**沉浸式角色陪伴/亲密互动对话引擎**（视觉小说式后端）。用户在浏览器/前端中输入动作与台词，后端通过"状态引擎 + 大模型生成"的混合架构，让角色以女性视角做出符合人设、意愿状态与剧情阶段的回应。

**技术栈**：Python 3.10+ · FastAPI · asyncio · Pydantic v2 · llama.cpp (GGUF, CUDA) · transformers (bitsandbytes/CPU) · FAISS + sentence-embedding 记忆检索 · SQLite/JSON 持久化。

**核心设计理念**：不是"输入→LLM→输出"的简单转发，而是：
- **状态引擎先行**：先解析用户动作、推进身体/心理/情绪/世界状态，生成"感官报告"。
- **LLM 只负责"说人话"**：把已提交的状态翻译成角色的自然回应。
- **输出后反哺**：解析模型回应，再回写状态（Post Process），形成双向闭环。

## 4. 对话主流程数据流水线

入口 `ChatOrchestrator._process_message_stream(session_id, user_input)`：

```
用户输入
  │
  ▼
① 解析  core/parser.parse_input + resolve_action_targets
  │       → 结构化动作列表（action_type / target_parts / intent_only / is_sexual…）
  ▼
② 动作执行（对每个动作按序）：
  │  - 时间跳转 / 地点变更 / 姿势变更（直接改世界状态）
  │  - 硬限制检查：_blocked_by_adult_eligibility / _blocked_by_hard_limit /
  │      _anal_intent_hard_limit（肛交意图检测，仅当角色硬限含肛交才拦截；imouto 已解除）
  │  - 意图(sexual_intent)：只记录成人语境，不执行身体动作
  │  - 拒绝对照：_sexual_response_level → explicit_refusal / gentle_boundary
  │  - 体力检查：stamina_cost < current 否则"体力不足"
  │  - 节拍循环：beat_controller.select_pattern → apply_beat_stimulation
  │      → 可能触发 orgasm / 中断(events)
  │  - 感官采样：sensation.generate → 生成"感官报告"文本
  ▼
③ 组装 Prompt  _build_system_prompt + _build_turn_prompt
  │      含：安全规则 / 硬限制底线 / 动作归属铁律 / 表达新鲜度 /
  │      CHARACTER_IDENTITY + USER_IDENTITY 资料 / 承接示范 /
  │      COMMITTED_STATE(状态摘要) + LONG_TERM_MEMORY + CONVERSATION_SUMMARY + 最近历史
  │      + 防复读要求（注入上一轮回复，禁止复用）
  ▼
④ 调用 LLM  llm_llama.generate / generate_stream
  │      流式：HEAD_LEN=14 首部复读检测，命中则中止重写一次；
  │      完整：生成后相似度兜底，重复则提高温度重写
  ▼
⑤ Post Process  core/post_processor.post_process → apply_post_adjustments
  │      从模型文本解析情绪/声音/拒绝/接受/高潮信号 → 反哺状态
  ▼
⑥ 落盘 & 记忆  更新 messages / 生成快照 / should_form_memory 判定
  │      → knowledge_service.add_memory；自动存档；防"取消回滚"
  ▼
⑦ 输出格式化  core/output_format.normalize_character_output
            （剥协议 / 剥角色名标签 / 引号分语言与括号 / 括号矫正 / 剔除成段英文）
```

## 5. 状态机体系（core/）

`CharacterState` 是组合根，持有以下子系统：

| 子系统 | 文件 | 职责 |
|---|---|---|
| 身体模型 | `body/parts.py` | 全身部位分区（胸/乳尖/阴蒂/小穴/后穴等），各部位唤起/湿润/准备度；`compute_global_arousal` 汇总 |
| 神经传导 | `body/neural.py` | 神经节点刺激-传导-衰减，认知抑制门控 |
| 高潮系统 | `orgasm.py` | 阶段机 plateau→orgasm→resolution；收缩波；强度/不应期 |
| 心理状态 | `mind_state.py` | 接受度/抵抗意志/拒绝真诚度/沉浸/边界感知/主动性；`get_dominant_state` |
| 情绪 | `emotion.py` | 多情绪 blend（shy/pleasure/overwhelm…）；认知门控/禁忌加成 |
| 自主神经 | `ans.py` | heart_rate 等生理信号 |
| 体力 | `physical_engine.py` | stamina 消耗/恢复/疲劳 |
| 敏感度 | `sensitivity.py` | 部位敏感度调制（累积/衰减） |
| 技能/新鲜度 | `skills.py` | 技能掌握、动作新鲜度奖励、身体感知 |

**每轮推进**：`s.tick(dt, w)` 会级联更新所有子系统（唤起衰减、情绪衰减、敏感度 tick、orgasm 阶段推进）。

## 7. 记忆体系（app/knowledge_service.py）

**三层隔离**（关键：每个角色+会话独立，不串）：
| 层 | 路径 | 作用域 |
|---|---|---|
| `relationship` | `data/knowledge/sessions/{session_id}` | 单会话的关系记忆（按会话隔离） |
| `character_private` | `data/knowledge/characters/{char_id}` | 角色私有记忆（跨会话） |
| `shared` | `data/knowledge/shared` | 全局共享记忆 |

**检索**：`retrieve_for_prompt` 按 `relationship → character_private → shared` 顺序合并；每层 `_LayerIndex` 用 **FAISS 向量 + 关键词**双路检索（embed 用 transformers/CPU 保证向量空间稳定，generate 用 GGUF）。

**记忆形成**：`should_form_memory(user_input, assistant_response, ...)` 判定事件（重要事件 importance≥0.3 存入）。**已扩展性事记忆**：命中性事关键词（骑乘/后入/口交/高潮/最敏感/最舒服…）且 arousal>0.4 时 importance=max(0.55)，使性交标志事件可入长期记忆。

**记忆压缩**：`memory_compactor.compact` 每 20 轮把旧完整回合用小模型压缩为 ≤800 字事实摘要（分小标题：事实与偏好/承诺与关系/冲突与边界/未解决事项），注入后续 prompt。

## 9. 模型后端与推理

- **主模型**：`llm_llama.py` → llama-server (GGUF, CUDA)，`models/qwen2.5-7b-instruct-abliterated-v2.Q4_K_M.gguf`，端口 8081，`-ngl 999` 全上 GPU，ctx 6144，temperature 0.95，**frequency_penalty 0.3**（压制套话）。≈46 tok/s。
- **小模型**：`llm_small_gguf.py` → 1.5B GGUF，端口 8082，`-ngl 0` **强制全 CPU**（8GB 显存不足以双模型并发上 GPU，避免拖垮 7B）。用于结构化提取/分类。
- **embed**：仍走 transformers(CPU)，保证 FAISS 向量空间与之前一致。
- **拒绝方向消融**：`REFUSAL_ABLATION=1`，推理时从残差流减去"拒绝方向"投影，削弱基座对齐先验（减少话题转移式推脱）。方向文件由 `train/extract_refusal_direction.py` 生成。
- **预热**：模型加载时用 1800 token 序列做一次 prefill，把首回合冷启动成本移到加载阶段。
- **后端切换**：`MAIN_MODEL_BACKEND=llama/transformers`（`model_backend.py` 路由）。当前用 llama。

## 12. 调度与并发（generation_coordinator.py）

- **单模型 FIFO**：`GenerationCoordinator` 保证任意时刻只有一个生成任务在跑，请求按队列顺序执行，避免 8GB 显存并发冲突。
- 按会话串行：同一会话已有未完成任务时新请求抛 `SessionGenerationBusyError`。
- 支持：排队状态、取消（QUEUED/RUNNING/CANCELLING）、流式事件发布、超时/长度/OOM 分类异常、shutdown 清理。

## 14. 性能与部署

- **启动**：`F:\python.exe -m uvicorn app.server:app --host 127.0.0.1 --port 8000`（或 venv）；先起 7B llama-server(8081) 与 1.5B llama-server(8082)。
- **性能**：7B ~46 tok/s（CUDA），1.5B CPU 结构化提取 ~3s。8GB 显存**不可并发两 llama-server 上 GPU**（小模型强制 CPU）。
- **持久化**：会话/状态 JSON + 快照 + 存档；记忆 FAISS 索引持久化到磁盘；`data/` 全部 gitignore。

## 15. 已知边界与后续建议

- **套话模板化**：7B 模板惯性使"心跳/脸红"类词仍偶现，彻底解决需换更大模型或针对性微调。
- **动作归属**：对"吻/含乳/解扣"等高频亲密动作，7B 在复杂前文下偶发归属漂移，规则已显著压制但非 100%。
- **组合连贯性**：体位切换/高潮推进已验证连贯；跨场景长记忆（如"上次做过什么")依赖 relationship 层检索，措辞不同时关联可能失效。
