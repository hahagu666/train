# Web 前端开发指南

> 日期：2026-08-07  
> 状态：前端实施基线  
> 适用后端：当前 `app/server.py` FastAPI 服务

## 1. 目标与边界

本项目后续前端改为本地浏览器 Web 应用。现有 Ren'Py 桌面前端保留但停止开发，不删除、不继续扩展，也不作为 Web 组件或状态架构的基础。

Web 前端的目标是完整承载当前后端已经提供的角色、会话、聊天、状态、历史、存档、时间线、知识、媒体、用户人设、应用设置和模型管理能力。

当前系统是本地单用户应用，不提供账号、鉴权和多用户隔离。前端不得把它部署为可被不可信网络访问的公共服务。

### 1.1 状态权威

- 后端是角色资料、资格判定、会话状态、世界状态、消息、快照、存档、知识和模型状态的唯一权威来源。
- 浏览器只保存界面偏好和临时编辑状态，不在本地复制一套业务真相。
- WebSocket 中间事件只驱动当前回合的临时显示；成功结束后以 `done`、`state` 以及必要的 REST 重取结果为准。
- 读档、回滚、撤回、重说、重置、分支后，必须重新获取会话详情、历史和完整状态。

### 1.2 第一阶段不做

- 不删除或重写 Ren'Py 文件。
- 不做公网部署、登录、云同步或多人同时使用。
- 不提供后端尚不存在的知识编辑/删除功能。
- 不把 `/api/chat` 作为正常聊天入口；它主要用于测试和无 WebSocket 环境。
- 不承诺主题切换已经有完整视觉实现。后端虽然保存 `theme`，Web 主题必须由新前端自行实现后才能开放。

## 2. 推荐技术架构

建议使用独立的 TypeScript 单页应用，首选 React + Vite。路由、请求缓存和表单库可在实施时选定，但必须保持以下模块边界：

```text
web/
├── src/
│   ├── api/
│   │   ├── http.ts              # URL、响应解包、错误归一化
│   │   ├── app.ts
│   │   ├── models.ts
│   │   ├── characters.ts
│   │   ├── sessions.ts
│   │   ├── knowledge.ts
│   │   └── media.ts
│   ├── chat/
│   │   ├── chat-socket.ts       # WS 生命周期、心跳、重连
│   │   └── chat-events.ts       # 事件联合类型与归约
│   ├── stores/
│   │   ├── app-store.ts
│   │   └── session-store.ts
│   ├── features/                # 按下文产品区域划分
│   ├── components/              # 通用基础控件
│   └── routes/
└── package.json
```

开发服务器代理：

- `/api` 转发到 `http://127.0.0.1:8000`。
- `/ws` 转发到 `ws://127.0.0.1:8000`，启用 WebSocket 代理。
- 生产构建优先由同源本地服务提供，减少 CORS 和 Origin 问题。
- 只保留一个包管理器和一个锁文件。

## 3. 信息架构与路由

| 路由 | 页面 | 核心用途 |
|---|---|---|
| `/` | 启动与角色首页 | 检查后端/模型，展示角色和最近会话 |
| `/characters/new` | 创建角色 | 结构化配置自定义角色 |
| `/characters/:characterId` | 角色详情 | 查看资料、媒体、资格、会话和角色知识 |
| `/characters/:characterId/edit` | 编辑角色 | 修改当前后端允许更新的字段 |
| `/characters/:characterId/sessions/new` | 新建会话 | 配置名称、称呼和开场剧情 |
| `/sessions/:sessionId` | 聊天工作区 | 对话、状态、存档和本会话工具 |
| `/sessions/:sessionId/history` | 历史与时间线 | 浏览消息/快照，撤回、重说、回滚和分支 |
| `/knowledge` | 共享知识 | 浏览和新增全局知识 |
| `/profile` | 用户人设 | 编辑姓名、自然语言人设和角色关系 |
| `/settings` | 设置与模型 | 应用设置、模型状态与模型操作 |
| `/diagnostics` | 数据诊断 | 查看损坏会话报告和后端状态 |
| `/about` | 关于 | 展示应用名称、版本和后端信息 |

窄屏采用顶栏和抽屉导航；宽屏采用固定左侧导航。聊天页可以使用自己的三栏布局，但不能把全局导航和角色栏叠加成重复导航。

## 4. 全局应用壳

### 4.1 顶层导航

显示：

- 角色
- 共享知识
- 用户人设
- 设置
- 诊断
- 关于
- 当前后端连接状态
- 当前模型状态简标

操作：

- 页面切换。
- 连接失败时手动重试。
- 模型未加载时进入设置与模型页。

状态：

- `checking`：首次检查中，显示骨架，不显示错误页面闪烁。
- `backend-offline`：无法访问 `/api/health`，提供重试和启动后端提示。
- `model-loading`：后端在线但主模型未就绪；允许浏览管理数据，禁止发送聊天。
- `ready`：正常工作。
- `model-error`：显示 `main_model_error`，提供重载入口。

启动读取建议并行请求：

- `GET /api/health`
- `GET /api/model/status`
- `GET /api/app/menu`

`/api/app/menu` 可用于首屏聚合，但各详情页仍按自身接口刷新，不能长期依赖启动快照。

## 5. 启动与角色首页

### 5.1 角色列表区

显示每个 `CharacterSummary`：

- 头像与姓名。
- 关系类型。
- 当前阶段。
- 简介预览。
- 是否存在历史会话。
- 最近会话的名称和最后活动时间，可由会话列表关联得到。

操作：

- 打开角色详情。
- 直接进入最近会话。
- 新建会话。
- 创建自定义角色。

数据：

- `GET /api/characters`
- `GET /api/sessions`
- 图片使用角色返回的 `avatar` 与 `avatar_revision`。

空状态：没有角色时显示“创建角色”，但预设角色正常情况下应始终存在；若为空应同时提示可能的数据初始化异常。

### 5.2 最近会话区

显示最近活动会话：角色、会话名、阶段、回合数、亲密度、信任度、最后活动时间。

操作：进入聊天、进入历史。不要仅根据首屏缓存判断是否有历史，点击后重新请求。

## 6. 角色详情

### 6.1 角色头部

显示：

- 头像、聊天背景预览、姓名、年龄、关系类型。
- 角色简介和背景故事。
- 成年确认与交互资格状态。
- 预设/自定义标识。

操作：

- 更换头像。
- 更换聊天背景。
- 自定义角色可编辑、删除。
- 预设角色不显示删除操作。
- 新建会话。

数据：

- `GET /api/characters/{id}`
- `GET /api/characters/{id}/eligibility`
- `PATCH /api/characters/{id}`
- `DELETE /api/characters/{id}`

删除必须使用确认对话框，并说明角色相关数据的实际影响需以后端行为为准。删除成功后返回首页并刷新角色和会话列表。

### 6.2 资料标签页

分组展示：

- 外貌：发型、眼睛、身高、体型、肤色、视觉年龄提示及扩展字段。
- 性格：害羞、傲娇、温柔、嫉妒、活泼、成熟及扩展参数。
- 说话方式：语气、第一人称、称呼、语气词、补充提示。
- 初始关系：衣着、亲密、信任。
- 偏好和边界：喜欢、厌恶、恐惧、软限制、硬限制。
- 高级仿真参数：默认折叠，只读展示身体、心理和情绪参数。

当前更新契约只支持 `name`、`age`、`adult_verified`、`character_description`、`backstory`、`appearance`、`body_params`、`initial_outfit`、`likes`、`dislikes`、`fears`。性格、说话风格、关系类型、初始亲密/信任、限制等创建字段当前不能完整更新，编辑页必须禁用这些字段或明确只读，不能假装保存成功。

### 6.3 会话标签页

显示该角色全部会话，来自 `GET /api/sessions?char_id=...`。

每行显示：会话名、阶段、回合数、关系值、地点、最后活动时间和活动状态。

操作：进入、历史、重命名、删除、重置。删除和重置属于高影响操作，必须二次确认。重置返回新的 `session_id`，前端必须替换路由，不能继续访问旧 ID。

### 6.4 角色知识标签页

显示角色私有知识，游标分页：

- 类型、内容、重要性、标签。
- 情绪效价和唤醒度。
- 时间信息及后端返回的其他只读元数据。

操作：新增知识。当前没有编辑/删除接口，不显示这些按钮。

API：

- `GET /api/knowledge/character/{char_id}?limit=...&cursor=...`
- `POST /api/knowledge/character/{char_id}`

## 7. 创建自定义角色

采用分步表单或单页分区表单，桌面宽屏可同时展示摘要预览。提交前保留用户所有输入，只有创建成功后清空。

### 7.1 表单分区

1. 基础资料：姓名、年龄、成年确认、关系类型、角色简介、背景故事。
2. 外貌：发型、眼睛、身高、体型、肤色。
3. 性格：六个 `0..1` 滑杆，旁边显示数值和文字等级。
4. 说话方式：语气、自称、对用户称呼、是否使用语气词、补充提示。
5. 初始状态：衣着、亲密度、信任度。
6. 偏好与边界：喜欢、厌恶、恐惧、软限制、硬限制，使用可删除标签输入。

关系类型固定为：`step_sister`、`classmate`、`childhood_friend`、`senior`、`teacher`、`neighbor`、`other`。界面显示中文，提交枚举值。

### 7.2 校验

- 姓名 1–40 字符。
- 年龄 0–120；勾选成年确认时年龄必须至少 18。
- 角色简介 1–1200 字符；背景故事最多 2000。
- 初始衣着 1–80 字符。
- 性格、亲密、信任均为 `0..1`。
- 喜好、厌恶、恐惧和限制各最多 20 项；客户端应限制单项长度并去重，后端仍是最终校验者。
- 不发送 `id`、媒体路径、revision、`is_preset`、资格结果或资格版本等服务端字段。

提交：`POST /api/characters`。成功后进入新角色详情，再单独上传头像和背景。

## 8. 用户人设

### 8.1 人设编辑

显示：姓名、性别、年龄、性格描述、提取特征、说话风格提示、外貌提示。

操作：

- 独立修改姓名：`PATCH /api/user/profile/name`，`{"name":"..."}`。
- 用自然语言重建/更新人设：`PUT /api/user/profile`，`{"description":"..."}`。

自然语言更新可能调用本地模型，应显示进行中状态且防止重复提交。返回后以响应 `data` 或重新请求 `GET /api/user/profile` 更新页面。

### 8.2 每角色关系与称呼

为每个角色显示当前关系和自定义称呼。提交：

```json
{
  "character_id": "...",
  "relation": "...",
  "custom_address": "..."
}
```

API：`POST /api/user/profile/relation`。这是全局用户人设配置，不应混入会话临时状态。

## 9. 新建会话

页面顶部固定显示所选角色摘要，主体配置以下字段：

- 会话名称，可空。
- 角色如何称呼用户，可选；若修改，先调用关系接口。
- 开场剧情：随机开场或从剧情卡中选择。

剧情卡来自 `GET /api/scenarios`，显示标题、阶段名称、地点和上下文摘要。不要展示原始剧情卡内容，也不要让用户手填剧情 ID。

提交 `POST /api/sessions`：

```json
{
  "character_id": "...",
  "name": "...",
  "scenario_id": "..."
}
```

随机开场不发送 `scenario_id` 或发送 `null`。明确选择的 ID 若不存在，后端返回 422，表单应保留并提示剧情已失效，随后刷新剧情列表。

成功响应含 `session_id`、`meta`、`opening` 和 `scenario_id`。应立即跳转聊天页。`opening` 先作为开场消息展示，随后通过会话详情/历史去重；不能假定 WebSocket 一定再次发送它。

## 10. 聊天工作区

### 10.1 宽屏布局

采用三个工作区，不照搬 Ren'Py 固定像素：

- 左栏 280–360px：角色、当前会话和该角色会话列表。
- 中栏弹性宽度：消息、流式回复、输入区。
- 右栏 320–420px：关键状态和世界状态。

中栏最小宽度应保证消息可读；空间不足时右栏变为抽屉，移动端左栏和右栏均由按钮打开。任何栏都不得通过动态文本改变基础列宽。

### 10.2 会话头部

显示角色、会话名、连接状态、模型忙碌状态、阶段、地点和当前时间。

操作：重命名、历史、存档、知识、更多菜单。更多菜单包含重置和删除，均需确认。

### 10.3 消息区

- 依据 `role` 区分用户、角色、系统和叙述消息。
- 使用稳定 `message_id`；旧数据缺少 ID 时仅在当前渲染中生成复合键，不能写回伪 ID。
- 显示时间、回合、快照关联和中断状态（字段存在时）。
- 流式回复是独立临时气泡，不在收到 token 时写入正式历史。
- `done.full_response` 替换临时气泡；随后刷新或合并后端已提交消息。
- 自动滚动只在用户接近底部时执行；用户阅读旧消息时不抢滚动位置。

### 10.4 输入区

- 多行文本框，1–6 行自动增长。
- 发送、停止生成、可选指令菜单。
- Enter 发送、Shift+Enter 换行；移动端保持明确发送按钮。
- 生成期间禁止再次发送，停止按钮保持可用。
- 断线、模型未加载或会话正在切换时禁用发送，并说明原因。
- 不在网络重连后自动重发上一条消息，避免重复回合。

### 10.5 关键状态

使用 `SessionStateSnapshot` 展示：

- 情绪、阶段、接受度。
- 信任、亲密。
- 心率、体力、疲劳。
- 唤起阶段和数值。
- 衣着。
- 时间、地点、隐私。
- 中断等回合标记。

数值仪表应有文字值，不能只靠颜色。状态先由 WebSocket `state.data` 更新；进入页面、重连或历史操作后由 `GET /api/sessions/{id}/state` 校准。

### 10.6 完整状态检查器

作为右栏的“详细”标签页或抽屉，展示：

- `character` 完整序列化状态。
- `world` 世界、天气、时间、地点和隐私信息。
- 当前 `snapshot_id`、`timeline_id`。

这是高级只读视图。后端对象结构较大且部分字段弱类型，前端应按已知字段分组，未知字段放入折叠的“其他状态”，不能因为新字段导致页面崩溃。

API：`GET /api/sessions/{id}/state`。

## 11. WebSocket 状态机

连接：`WS /ws/chat/{session_id}`。

### 11.1 客户端消息

```json
{"type":"message","content":"..."}
{"type":"stop"}
{"type":"ping"}
```

### 11.2 服务端事件处理

| 事件 | 前端行为 |
|---|---|
| `opening` | 追加或去重开场消息 |
| `action_start` | 显示“正在理解/执行动作”的短暂状态 |
| `blocked` | 显示动作受限提示，不自行推断业务结果 |
| `orgasm` | 记录当前回合事件，可在状态区短暂提示 |
| `event` | 显示叙事事件提示，如中断 |
| `generating` | 进入生成态，创建临时回复气泡 |
| `token` | 追加到临时缓冲；是否逐字展示由设置决定 |
| `memory_formed` | 提示形成新记忆，并使会话知识缓存失效 |
| `state` | 更新关键状态、快照 ID |
| `done` | 以 `full_response` 提交最终显示，结束生成态 |
| `cancelled` | 清空或标记未提交临时回复，重取状态/历史 |
| `error` | 结束生成态，显示错误，必要时重取状态/历史 |
| `pong` | 更新连接存活时间 |

`blocked`、`event` 和 `orgasm` 是过程事件，不代表回合已经持久化。只有完成提交后才将新状态视为稳定状态。

### 11.3 连接生命周期

- 进入会话页后连接，离开时主动关闭并停止重连。
- 空闲时每 20–30 秒发送应用层 `ping`。
- 未收到 `pong` 或连接关闭时采用带抖动的指数退避重连，例如 1s、2s、4s、8s，最高 30s。
- 重连成功后并行重取会话详情、历史和状态。
- 重连期间保留未发送输入草稿，但不重发已发送消息。
- 服务器当前没有 resume token 或事件序号，前端不得假设能续接中断的 token 流。
- `stop` 是协作式取消，点击后显示“正在停止”，收到 `cancelled`、`done` 或 `error` 后退出该状态。

### 11.4 逐字显示设置

后端始终通过 WebSocket 发 token。`stream_responses` 在 Web 前端解释为视觉策略：

- 开启：实时渲染 token 缓冲。
- 关闭：继续接收并缓存 token，但只在 `done` 时显示 `full_response`。

无论开关如何，最终文本都以 `done.full_response` 为准。错误、取消、离开会话时清理临时缓冲。

## 12. 历史与时间线

页面使用左侧消息/回合列表与右侧快照详情，或按时间线纵向组合。进入时请求：

- `GET /api/sessions/{id}/history`
- 必要时 `GET /api/sessions/{id}/snapshots/{snapshot_id}`

显示：

- 完整消息历史。
- 快照列表、操作类型、时间、回合。
- 当前快照和时间线 ID。
- 选中快照的状态、世界和消息截断信息。

操作：

- 重说：`POST /api/sessions/{id}/retry?turn=N`，body `{"suggestion":"..."}`。
- 撤回：`POST /api/sessions/{id}/retract?turn=N`。
- 回滚：`POST /api/sessions/{id}/rollback`，body `{"snapshot_id":"..."}`。
- 从快照创建分支：`POST /api/sessions/{id}/branch`。
- 继续当前会话。

这些操作会改变持久化状态或产生新时间线，必须显示确认及影响范围。执行期间禁用聊天发送；成功后使会话详情、历史、状态、会话列表和存档缓存全部失效。重说接口当前是非流式 HTTP 操作，应显示不可取消的处理中状态。

空状态必须分别表达“没有消息”“没有快照”和“历史加载失败”。

## 13. 存档与分支

存档面板显示名称、创建时间、回合、阶段和预览。

API：

- `GET /api/sessions/{id}/saves`
- `POST /api/sessions/{id}/saves`，`{"name":"..."}`
- `POST /api/sessions/{id}/saves/load`，`{"slot_id":"..."}`
- `DELETE /api/sessions/{id}/saves/{slot_id}`
- `POST /api/sessions/{id}/branch`，使用 `from_slot` 或 `snapshot_id`，并提供 `name`

操作规则：

- 创建存档成功后刷新列表。
- 读档前确认，成功后关闭面板并重新获取消息、状态、历史。
- 删除存档前确认。
- 创建分支成功后提示新会话名称，并跳转 `new_session_id`。
- `_autosave` 若由后端列表返回，应标记为自动恢复点，不与普通命名存档混淆。

`auto_save` 的语义是成功提交每一回合后由后端创建自动恢复点，不等于是否持久化普通会话；普通会话始终持久化。

## 14. 知识管理

### 14.1 共享知识页

显示全局知识，支持游标分页和新增：

- `GET /api/knowledge/shared`
- `POST /api/knowledge/shared`

### 14.2 会话知识

在聊天工作区抽屉或独立标签页显示关系层记忆：

- `GET /api/knowledge/session/{session_id}`
- `POST /api/knowledge/session/{session_id}`

### 14.3 新增知识表单

字段：

- 内容，必填。
- 类型：`episodic`、`semantic`、`emotional`、`procedural`。
- 重要性 `0..1`。
- 标签。
- 情绪效价 `-1..1`。
- 情绪唤醒 `0..1`。

当前 API 只支持列出和新增。没有更新、删除、搜索或批量导入接口，对应控制不得出现为可用按钮。游标是后端不透明字符串，前端只保存并原样传回。

## 15. 图片选择、裁剪与上传

浏览器使用文件输入或拖放，不调用 Windows 原生选择器。

流程：

1. 用户选择本地 JPEG、PNG 或 WebP。
2. 客户端初筛：静态图片、文件不超过 15 MiB，并解码尺寸。
3. 使用 object URL 显示裁剪预览。
4. 头像锁定 1:1，背景锁定 16:9。
5. 将裁剪框换算为原图归一化坐标 `0..1`。
6. 使用 multipart/form-data 上传原文件与 `crop_x/y/width/height`。
7. 成功后刷新角色详情并使用新 revision URL。
8. 替换图片或组件卸载时调用 `URL.revokeObjectURL()`。

API：`POST /api/characters/{id}/media/{avatar|background}`。

服务端最终限制：

- 最大 15 MiB、4800 万像素。
- 不支持动图。
- 裁剪最短边至少 128 原图像素。
- 头像输出 512×512 JPEG。
- 背景输出 1920×1080 JPEG。

显示图片时使用：

```text
/api/media/{character_id}/{kind}?v={revision}
```

不要另建浏览器文件缓存清单；依赖 HTTP 缓存和 revision 查询参数。上传失败保留裁剪状态并展示后端具体错误。

## 16. 设置与模型管理

### 16.1 应用设置

API：

- `GET /api/app/settings`
- `PATCH /api/app/settings`

当前字段：

- `stream_responses`：是否逐字显示回复。
- `auto_save`：成功回合后是否创建自动恢复点。
- `theme`：只有 Web 前端实现完整主题变量和持久应用后才展示。
- `language`：当前仅支持 `zh-CN`，无需展示不可选的控件。

每次 PATCH 只提交变化字段。后端禁止未知字段，前端应把 Pydantic 422 细节映射到对应控件。

### 16.2 模型管理

显示：

- 主模型是否加载、设备、量化方式、状态、忙碌和错误。
- 小模型是否可用、是否加载。
- 加载进行状态。

操作：

- 预加载：`POST /api/model/preload`。
- 卸载：`POST /api/model/unload`。
- 重载：`POST /api/model/reload`。

模型忙碌时卸载/重载可能返回 409；加载失败可能返回 503。操作按钮必须在请求期间禁用。模型状态页可在加载期间低频轮询 `GET /api/model/status`，建议 1–2 秒；正常就绪后降至 10–30 秒或仅在窗口聚焦/操作后刷新。

卸载和重载会影响当前生成，应提示影响并要求确认。聊天页根据 `main_model_loaded` 和 `main_model_busy` 控制发送状态，但不能把全局 busy 永久缓存。

## 17. 数据诊断与关于

### 17.1 损坏会话

`GET /api/sessions/corrupted` 返回后端启动时发现的损坏会话报告。页面显示可用标识、路径/原因等实际返回字段，未知字段折叠展示。

当前没有 Web 修复或删除损坏会话的专用 API，因此只提供刷新和诊断信息，不提供虚假的“修复”按钮。

### 17.2 关于

`GET /api/app/about` 显示名称、版本和后端类型。可附加浏览器前端构建版本，但需与后端版本分开标记。

## 18. HTTP 客户端约定

后端当前响应格式不统一，客户端必须在单一适配层处理：

1. 标准包装：`{"success":true,"message":"","data":...}`。
2. 原始对象或数组，例如角色列表、会话列表、剧情列表、模型状态。
3. FastAPI 错误：`{"detail":"..."}` 或 422 的结构化 `detail[]`。
4. 自定义 ValueError：`{"success":false,"code":"INVALID_REQUEST","message":"...","data":null}`。

建议所有 API 函数返回解包后的领域数据，并把失败统一为：

```ts
type ApiError = {
  status: number;
  code?: string;
  message: string;
  fields?: Record<string, string>;
  raw?: unknown;
};
```

规则：

- 不在组件中重复判断 `response.data.data`。
- 只把明确成功的 2xx 当成功；标准包装若 `success === false` 仍抛错。
- 404 显示资源不存在并提供返回路径。
- 409 显示忙碌/冲突，不自动重试变更请求。
- 422 映射字段错误；无法映射的错误显示在表单顶部。
- GET 可有限重试；POST/PATCH/DELETE 默认不自动重试，避免重复创建或重复操作。
- 所有用户可触发请求应支持 AbortController；离开页面时取消无关 GET。

## 19. 缓存与同步

建议缓存键至少包含：

- `characters`
- `character:{id}`
- `sessions:{characterId|all}`
- `session:{id}`
- `history:{id}`
- `state:{id}`
- `saves:{id}`
- `knowledge:{layer}:{ownerId}`
- `model-status`
- `settings`

失效规则：

- 创建/更新/删除角色：角色列表、详情和首页。
- 媒体上传：角色列表、详情和所有使用该媒体的视图。
- 创建/删除/重命名/重置会话：全部相关会话列表。
- 成功回合：会话详情、历史、状态、会话列表和会话知识。
- 读档、撤回、重说、回滚：历史、状态、详情、存档和会话列表全部重取。
- 分支：全局和角色会话列表重取。

多标签页当前共享后端进程级 `active_session_id`。首版应明确提示不建议多标签同时聊天；不能用 active ID 推断当前路由会话，所有请求和 WebSocket 都应显式带 `session_id`。

## 20. 错误、空状态与反馈

每个数据区必须独立处理：加载、成功、空、失败、刷新中。整页不因一个次要面板失败而空白。

- Toast 用于成功反馈和非阻塞错误。
- 表单错误显示在字段附近。
- 模型离线、WebSocket 断线、会话不存在等阻塞错误显示在操作位置。
- 删除、重置、读档、回滚、撤回、卸载模型使用确认对话框。
- 长操作显示明确阶段，不使用无限转圈而无文字。
- 后端错误文本可以展示，但不要暴露本地堆栈或拼接 HTML。

## 21. 响应式与可访问性

- 桌面宽屏优先满足高频聊天和状态对照；不使用营销式首页或大型 hero。
- `>= 1280px`：聊天三栏。
- `768–1279px`：左栏保留，状态右栏改抽屉。
- `< 768px`：单列聊天，角色和状态均为抽屉；输入区固定但不得遮住最后消息。
- 键盘可完成导航、表单、发送、停止、对话框确认和裁剪基本操作。
- 图标按钮提供可见 tooltip 和无障碍名称。
- 焦点样式明确；对话框打开后锁定焦点，关闭后还原触发点。
- 颜色不是状态的唯一表达；进度条和仪表都显示文字。
- 长角色名、长会话名、长标签和长错误必须换行或截断并可查看完整内容。
- 尊重 `prefers-reduced-motion`，流式文字不使用逐字淡入动画。

## 22. 本地安全约束

当前后端无认证，包含角色私密资料、会话、状态和知识管理能力。实施 Web 前必须遵守：

- 默认只监听 `127.0.0.1`。
- 不向局域网或公网暴露端口。
- 生产前端优先与 API 同源。
- CORS 不应在 `allow_credentials=True` 时配置通配符 `*`；开发时只允许实际开发服务器 Origin。
- WebSocket 服务端当前没有校验 Origin，公开部署前必须补齐。
- 用户文本一律按纯文本渲染；若未来支持 Markdown，必须使用严格净化器，禁止原始 HTML。
- 图片上传仍由服务端验证，客户端校验只用于体验。
- 不把完整会话、知识或状态写入 localStorage、日志、遥测或第三方错误平台。

## 23. 当前后端限制清单

前端实现时必须显式接受这些限制，不能以 UI 掩盖：

1. 响应包装格式不统一，需要客户端适配层。
2. `active_session_id` 是进程级全局状态，多标签可能互相切换。
3. 没有登录和用户隔离。
4. WebSocket 没有 schema version、事件序号或断点续传。
5. 新会话开场可同时来自创建响应和 WebSocket，存在去重要求。
6. 停止生成是协作式取消，不保证点击后立即终止。
7. 中间过程事件和状态不等于已持久化提交，失败时可能回退。
8. 完整状态结构较大且部分弱类型，前端需容忍未知字段。
9. 创建与更新角色字段不对称，部分创建字段目前不能编辑。
10. 知识只有列出和新增，没有编辑、删除和搜索 API。
11. CORS 通配符与 credentials 配置、WebSocket Origin 校验需要在浏览器交付前加固。
12. 情景阶段、会话阶段及重复关系值应以后端最终会话状态为准，不在前端自行计算。

## 24. 实施顺序

### Phase 1：基础壳与契约层

- 建立 Web 工程、代理、路由、设计变量和 API 错误适配。

- 为所有当前 REST 契约建立 TypeScript 类型和契约测试。

### Phase 2：角色和会话入口

- 角色详情、结构化创建、受限编辑、媒体裁剪上传。

### Phase 3：聊天闭环

- WebSocket 状态机、消息列表、输入和停止。
- 关键状态、完整状态、重连重同步。

### Phase 4：历史和持久化工具

- 历史、快照、重说、撤回、回滚。

### Phase 5：知识与诊断

- 三层知识浏览和新增。
- 损坏会话诊断、关于页、完整模型管理。
- 响应式、无障碍和错误场景收尾。

## 25. 测试与验收

### 25.1 自动化测试

- API 适配层覆盖标准包装、原始响应、404、409、422 和自定义错误。
- WebSocket reducer 覆盖所有事件、重复 opening、token/done 一致性、取消和错误清理。
- 表单覆盖角色边界、未知字段不提交、成年确认逻辑和列表去重。
- 媒体覆盖比例、归一化坐标、超大文件、无效图片和 object URL 回收。
- 历史操作覆盖缓存失效和路由替换。
- 组件测试覆盖加载、空、错误、禁用和确认状态。

### 25.2 浏览器端验收

1. 后端关闭、模型加载中、模型失败和模型就绪四种启动状态均有明确界面。
2. 角色与会话数据可以刷新，长文本和空列表不破坏布局。
3. 自定义角色所有字段可配置，校验错误保留输入，服务端字段不可伪造。
4. 头像和背景可选择、裁剪、上传并立即更新，刷新后仍正确。
5. 可选择随机或具体剧情创建会话，开场文本不重复。
6. 正常发送、逐字显示关闭、停止、服务端忙碌、超时和断线重连均可恢复。
7. 重连不会重复发送用户消息，最终消息和状态与后端历史一致。
8. 历史浏览不改变当前会话；重说、撤回、回滚后消息和状态同步。
9. 存档、读档、删除存档和从存档/快照分支均有确认和正确跳转。
10. 三层知识可分页浏览和新增，不出现无后端支持的编辑/删除操作。
11. 设置中的每个可见控件都产生实际行为。
12. 桌面、平板和移动宽度下无重叠、遮挡、不可达按钮或水平页面滚动。
13. 使用浏览器控制台和网络面板检查无未处理异常、重复请求风暴或对象 URL 泄漏。

### 25.3 交付门槛

- 类型检查、单元测试和生产构建通过。
- 使用实际 FastAPI 后端完成端到端浏览器测试，不以 mock 代替最终验收。
- 使用桌面和移动视口截图检查布局，并人工完成聊天、媒体、历史、存档和设置主流程。
- 后端仍只绑定本机，CORS 和 WebSocket Origin 策略符合本地 Web 运行方式。
